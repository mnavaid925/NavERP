{% extends "base.html" %} {% block title %}Receipt → Bin Map{% endblock %} {% block content %} {% comment %} 6.18 Inventory & Warehouse Integration — the Receipt → Bin map (apps/procurement/views/InventoryWarehouseIntegration/ReceiptBinMap.py). READ-ONLY. No model, no form, no migration. It follows each goods receipt past the staging location the GRN detail page shows, to the bin the goods actually reached. THE TRAIL, because it is the one thing easy to get wrong here: a goods receipt's stock moves carry the GRN's number and land in STAGING; the bin is reached later by a putaway task, whose moves carry the TASK's number. So the bins below come from each receipt's putaway tasks (the task's to_location IS the bin) and never from a GRN-number stock lookup, which could only ever find staging. Stock received but never put away has no bin — it is still in staging, which is what the unputaway figure reports. Context consumed: page_obj, object_list (row dicts), q, locations, status_choices, selected_location, selected_status, date_from, date_to, stats{receipts, fully_putaway, partially_putaway, in_staging}, row_cap, truncated, reference_note, links. Row keys: grn, grn_url, staging_location, received_qty, bins[{location, path, quantity, capacity, fullness_pct, capacity_css}], putaway_tasks[{task, url, status, status_css, to_location}], unputaway_qty, is_unputaway, putaway_css. Every row url is ALREADY reversed in the view. The status select compares selected_status against the exact GoodsReceiptNote.STATUS_CHOICES values; the location select compares with |stringformat:"d" (never |slugify). {% endcomment %}
