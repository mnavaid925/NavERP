ONE template for both, driven by `is_edit` (crud_create passes is_edit=False and NO obj; crud_edit passes is_edit=True and obj). The form carries exactly the ten editable header fields: location, movement_type, purpose, reference, issue_date, org_unit, gl_account, requested_by, reservation, notes. Everything the document PRODUCES is excluded and none of it is accepted from a POST — number is minted by TenantNumbered.save(), and status, adjustment, issued_by, posted_at and cancelled_at are stamped by submit() / post() / cancel() alone. A document whose "posted" flag could be typed in would not be evidence of anything. Lines are NOT on this form. They are added one at a time on the detail page, because each one needs the item's current on-hand figure beside it — which only exists once the document knows its location. Field help is keyed off field.name so it stays correct if the form order changes, and every {% if %} branch falls through to field.help_text — the model's own help text is already written and a silent blank would be worse than a duplicate. Each label is bound to its widget with for="{{ field.id_for_label }}". The return-to-stock / return-to-vendor distinction gets its own explainer card rather than a line of help text: it is the one thing on this form that is expensive to get wrong, and the two read almost identically in a dropdown. {% endcomment %}

Which kind of return is this?

two documents, two very different outcomes

Choose Return to stock here when material that was drawn for a job comes back unused and goes onto the same shelf it came off. Stock at the location goes up; nothing leaves the building; no money changes hands.

Choose Return to vendor instead — a different document, 6.12's [RMA-] — when goods are going back to the supplier. Those ship off site and expect a credit note against the purchase. Filing one as the other leaves either stock on hand nobody can find, or a vendor credit nobody ever claims.

What happens next

stock does not move here
  1. Create the document — this form. It starts as a draft with no lines.
  2. Add lines on the document itself. Each shows what the location holds right now, so a shortfall is visible before you post rather than only as a refusal afterwards. Every line is valued automatically at the item's moving-average cost — nobody types a price.
  3. Submit (optional) marks it finished and freezes the lines. A draft can be posted directly; a one-person store issue does not need a second pair of eyes to become a movement.
  4. Post mints a draft stock adjustment in SCM, signed for this document's direction. Stock changes when that adjustment is posted there, not here — one code path writes the stock ledger and it lives in the app that owns it.

A posted document can never be cancelled or deleted. The correction is a mirror document — a return against the same location for the same items — which is why the direction lives on this form rather than in two separate models.
