What the four decisions mean

Accepted is included in the release and becomes a requisition line under the vendor shown on the row. Snoozed needs a future date and says "not now, ask me again then". Dismissed says "we looked and decided no" — which is exactly the answer nothing in the system could record before this run existed. Pending means nobody has looked yet.

The vendor on each line is a default taken from the replenishment policy, not a verdict. Change it here and the line moves into that vendor's requisition at release.

Supplier list capped This workspace has more supplier and vendor parties than the row dropdowns will carry, so each row offers the first {{ vendor_option_cap }} by name — plus whichever supplier is already on that line, which is never dropped. The list is repeated inside every row's form, so an uncapped register would add thousands of entries to this page. To point a line at a supplier outside the list, set it as the item's replenishment policy preferred vendor and re-generate, or change the vendor on the requisition after release.

Danger zone

Deleting a run removes it and every suggestion on it. Nothing outside the run is touched — no requisition, no reorder rule, no policy and no stock. If the run has already been released, delete is not offered at all: those requisitions exist and this is the only record of where they came from.
