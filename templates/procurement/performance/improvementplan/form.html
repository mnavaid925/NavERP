{% extends "base.html" %} {% block title %}{% if is_edit %}Edit Improvement Plan{% else %}Open an Improvement Plan{% endif %}{% endblock %} {% block content %} {% comment %} 6.16 Supplier Performance & Evaluation — improvement-plan create-or-edit. ONE template for both, driven by `is_edit` (crud_create passes is_edit=False and NO obj; crud_edit passes is_edit=True and obj). EVERY obj.* read below is inside an is_edit branch — on create there is no obj and an unguarded read is a silently blank region (L8). Context contract: form, is_edit, and on EDIT ONLY obj. THE FORM CARRIES enctype="multipart/form-data" — the `evidence` FileField needs it, and without it the browser posts only the filename, so the upload silently never arrives. The form's clean_evidence applies the extension allowlist and the 20 MB cap; both are printed next to the field so the refusal is not the first time anyone hears about them. The form carries twenty fields: title, supplier, scorecard, kpi, severity, finding, root_cause, corrective_actions, support_provided, success_criteria, start_date, target_close_date, next_review_date, extended_close_date, owner, supplier_owner_name, supplier_owner_email, escalated_suspension, evidence, evidence_url. `status` and `outcome` are NOT among them: the lifecycle belongs to the five verbs on the detail page, and an outcome typed here would be a result nobody signed off. `number` (auto SIP-#####), `tenant`, `actual_close_date`, the acknowledgement stamps and the verification stamps plus `closure_note` are all system-set and have no input either — a stamp that could be typed over would stop being evidence of anything. Four rules are enforced by the MODEL, not by anything here, and are raised together so this page shows every problem at once: the plan must not close before it starts; an extension must fall STRICTLY AFTER the original target; an outcome belongs only to a closed plan (which is why there is no outcome field here at all); and an escalation must point at a suspension in this workspace AND against this same supplier. The help text below explains each of them where the field renders. Field help is keyed off field.name so it stays correct if the form order changes. Each label is bound to its widget with for="{{ field.id_for_label }}". {% endcomment %}

{{ field }} {% if field.name == "title" %}
One line somebody scanning the register will recognise — the problem, not the ceremony. “Late deliveries on the Kanto line” beats “Q3 PIP”.
{% elif field.name == "supplier" %}
Who the plan is with. The list is this workspace’s supplier and vendor parties.
{% elif field.name == "scorecard" %}
The period whose performance opened this plan — the evidence behind it. Optional, but a plan tied to a period shows up on that period’s page, where the number and the work to fix it stay attached to each other.
{% elif field.name == "kpi" %}
The failing KPI, when one metric drove this. Leave blank when the problem is a pattern rather than a single number — a plan citing a KPI appears on that KPI’s definition page.
{% elif field.name == "severity" %}
How bad it is. Severity drives triage and nothing automatic: a critical plan is not a different workflow, it is the same workflow somebody reads first.
{% elif field.name == "finding" %}
What was actually observed, in the supplier’s language as much as ours. This is the paragraph that gets quoted back if the plan is ever disputed.
{% elif field.name == "root_cause" %}
Why it happened. Optional — and a plan with no root cause is a plan that fixes a symptom, so it is worth coming back to fill in once the supplier has investigated.
{% elif field.name == "corrective_actions" %}
What was agreed would be done about it. Narrative on purpose: a plan is one row here, and a real action list belongs in its own register rather than crammed into a text box that nothing can count.
{% elif field.name == "support_provided" %}
What we are doing to help — forecast visibility, a joint audit, revised drawings. A supplier told to improve with no help is being managed, not developed.
{% elif field.name == "success_criteria" %}
What “fixed” looks like, in numbers: on-time delivery above 95% for two consecutive months, not better delivery. Without this, closing the plan is an opinion.
{% elif field.name == "start_date" %}
When the plan period begins.
{% elif field.name == "target_close_date" %}
The date agreed at the outset. It must not fall before the start date, and it stays as the record of what was originally agreed even if an extension is granted later.
{% elif field.name == "next_review_date" %}
When the next check-in falls due. Optional — but a plan nobody reviews between opening and closing is one nobody works.
{% elif field.name == "extended_close_date" %}
A granted extension. It must fall strictly after the target close date — an “extension” on or before the agreed date would be a way to quietly re-write what was agreed. Once set, every “past due” reading is measured against this instead.
{% elif field.name == "owner" %}
Who owns this on our side. Optional, and a plan with no owner is a plan with nobody chasing it.
{% elif field.name == "supplier_owner_name" %}
Who owns it on theirs. Their name here is what makes the acknowledgement mean something later.
{% elif field.name == "supplier_owner_email" %}
Where the plan and its reviews get sent.
{% elif field.name == "escalated_suspension" %}
The block-register entry this plan escalated to. Blocking a vendor happens in the suspension register with its own request → decide → lift lifecycle — this field only points at it, because a second blocking flag would disagree with the real one within a quarter. It must be a suspension against this same supplier.
{% elif field.name == "evidence" %}
Supporting proof — the audit report, the failure photographs, the signed plan. Allowed: pdf, doc, docx, xls, xlsx, csv, txt, png, jpg, jpeg, gif, webp, zip. Maximum 20 MB.
{% elif field.name == "evidence_url" %}
A link to evidence held elsewhere — a QMS record, a shared drive. Just as good as an upload: proof does not have to be copied here to be proof.
