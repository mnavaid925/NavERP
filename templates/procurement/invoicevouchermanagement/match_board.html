Nothing else exists here. Four things this page must NOT do: 1. Count `g.variances|length` as the invoice's exception total. `variances` is the slice the view put in the group while blocking_count / warn_count are computed over the whole invoice — the two are not the same number. 2. Assume a row is acceptable. Each variance carries a `can_accept` flag (open or disputed resolution AND a parent invoice that is not locked) and an `actions` collection; both are rendered defensively, so a row without them simply shows no button rather than offering a transition the view would reject. 3. Interpolate a variance message into a confirm() handler. `message` is matcher text and can carry an apostrophe; ' does not escape inside an event-handler attribute and a throwing confirm does not preventDefault, so the POST would fire unconfirmed. Only the integer {{ v.pk }} is used. 4. Present variance_pct beyond 4 dp — it is a Decimal(9,4) column. The board is ordered OLDEST EXCEPTION FIRST: the invoice whose exception has waited longest heads the page, which is why `oldest_at` is shown in every card header. stats.overdue counts variances past their due date that are NOT in a terminal resolution — accepted / credit_memo / debit_memo / short_paid / cancelled are terminal, so they never age into it. Badges compare the frozen CHOICES keys and always end with a badge-slate fallback. {% endcomment %}
