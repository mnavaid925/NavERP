THIS PAGE EXISTS BECAUSE A RAW NUMBER IS MEANINGLESS WITHOUT ITS SCALE. An FHR of 100 is excellent; a D&B SER of 9 is dangerous. So the value is never shown alone: it is shown against `scale`, and the direction is stated in this metric own words via scale.direction, scale.safest and scale.riskiest — never as a generic "higher is better". When scale.registered is False (metric = "other") the page says plainly that no scale is registered and that the band is therefore Not banded, and draws NO meter: a bar with no meaning behind it is worse than no bar. `breaches_minimum` is ADVISORY and the page says so in those words. It colours a badge against `minimum_acceptable` and stops nothing — no PO hold, no payment block, no award refusal. The only place a vendor is actually blocked is the 6.4 suspension register. `assessment` is the party latest scm.SupplierRiskAssessment, CITED and never recomputed — SCM 4.2 owns the internal four-factor composite and 6.17 ships no rival headline. Its level renders in a NEUTRAL badge-slate chip on purpose: this page reports 4.2 verdict, it does not re-grade it. Nullable-FK discipline (L10): evidence, captured_by, reviewed_by and alert are all nullable, so every read of them sits inside an {% if %} branch — a `default:` filter argument on a None FK raises VariableDoesNotExist and 500s. `party` is PROTECT and never null. The meter is gated on obj.is_banded, never on obj.risk_position: the template language has no None literal, so `{% if obj.risk_position %}` would also hide a position of 0.00 — the safest possible reading, rendered blank. No |safe anywhere: notes, review_note and source_ref are staff-authored text. `source_ref` renders as TEXT and never inside an href.
