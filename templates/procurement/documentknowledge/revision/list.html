How the revision chain works

why uploading is not the same as publishing

Uploading a file never changes which version is current. A new revision lands awaiting approval and sits behind the current one; approving it moves the document's pointer, copies its text into what the register searches, and puts a still-draft document into force. Approval only ever moves forward — a revision at or below the current number cannot be approved, which is what keeps the chain linear.

Earlier approved revisions keep their approval and are marked superseded. They were approved, and the record of what was in force is not rewritten. Only an unapproved revision that the document does not point at can be deleted, and deleting it removes the record without reclaiming the stored file from disk.

The checksum shown against each file is taken from the bytes that arrived and recorded once. Text is read from PDFs that carry a text layer and from plain-text uploads; when a file has no text to read, the row says so rather than leaving an empty column that looks like a fault.
