{% extends "base.html" %} {% block title %}Receiving Console{% endblock %} {% block content %} {% comment %} 6.12 Goods Receipt Note (GRN) Creation — the receiving console. A COMPUTED board. It owns NO state: every ASN below is a 6.11 procurement.AdvancedShipmentNotice, and booking one writes a DRAFT scm.GoodsReceiptNote (the 6.1 precedent — procurement drafts INTO the SCM spine). It does NOT receive the goods: scm:goodsreceipt_receive stays the single stock writer, so nothing on this page posts a StockMove or a JournalEntry. Rows disappear from the board once a receipt already carries their supplier reference as its delivery-note reference. TEMPLATE ↔ BACKEND INPUT-NAME CONTRACT (the one place the two must agree byte-for-byte — renaming any of these silently drops the value): receipt_date, location, notes, and one qty_ per line. The mint-lots form is a SEPARATE POST carrying only the CSRF token, and it is rendered only when `can_mint` — that verb is @tenant_admin_required, so showing it to a member would offer a button that dead-ends on a 403. The book form is NOT gated: its verb is @login_required only. Context consumed: object_list (the paginated ASN page — NOT iterated; `rows` is built from it and is what this template loops), page_obj, q, status_choices, vendors, purchase_orders, locations, arrival, arrival_choices, status (the SANITIZED ?status=, echoed back — never request.GET.status, which may hold a value the board rejected), can_mint, stats. {% endcomment %}
