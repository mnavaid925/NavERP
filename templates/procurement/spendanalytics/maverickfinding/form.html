Which rule this breaches. It sets the default severity and it is what the dashboard groups by, so pick the one that actually describes the breach rather than the closest match.
{% elif field.name == "severity" %}
Override the default the reason implies. High severity is what the KPI strip counts, so keep it for spend you would genuinely escalate.
{% elif field.name == "supplier_invoice" %}
The invoice the spend landed on. Required unless the finding points at a purchase order instead.
{% elif field.name == "invoice_line" %}
Optional. Choose a line when only one item on the invoice is off-contract or above price — leave it clear when the whole document is the problem.
{% elif field.name == "purchase_order" %}
Use this for order-side breaches: a PO raised with no requisition, or orders split below an approval threshold.
{% elif field.name == "vendor" %}
Always required. It is stamped on the finding so the dashboard can group by supplier without joining back through four tables.
{% elif field.name == "category" %}
Optional. Leave it clear when nothing classifies the spend — the dashboard shows those together as “(Unclassified)” rather than dropping them.
{% elif field.name == "org_unit" %}
Optional. There is no department column on an invoice, so this is normally resolved through the purchase order’s requisition; findings with no PO stay unassigned.
{% elif field.name == "contract" %}
The agreement that should have covered this purchase, when one exists. Leave it clear on a “no active contract” finding — that is the point of the finding.
{% elif field.name == "catalog_item" %}
The approved catalogue entry the buyer should have used, or the one whose price was exceeded. Only approved, active entries are offered.
{% elif field.name == "document_date" %}
The date on the source document, not today. Every trend, aging bucket and date filter reads this field.
{% elif field.name == "amount" %}
What was actually spent, at face value in the document’s own currency. Nothing on this page converts between currencies.
{% elif field.name == "benchmark_amount" %}
What it should have cost — the contracted or catalogue price. Leave it blank for a routing breach: leakage is only meaningful where there is a price to compare against.
{% elif field.name == "is_addressable" %}
Clear this when the spend was never routable through a contract or a catalogue. Non-addressable spend is excluded from the maverick-rate denominator so the percentage stays honest.
{% elif field.name == "detail" %}
Why this was raised, in plain words. The scan writes this itself; on a hand-raised finding it is the only explanation anyone will have.
