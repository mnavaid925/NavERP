{% extends "base.html" %} {% block title %}Spend Dashboards{% endblock %} {% block content %} {% comment %} 6.14 Spend Dashboards — procurement:spend_dashboard, apps/procurement/views/SpendAnalyticsReporting/Dashboard.py. A COMPUTED, READ-ONLY page. It owns no table and contributes no migration: every figure is read on the fly through apps/procurement/analytics.py over records that already exist (6.13 supplier invoices on the invoiced basis, SCM 4.1 purchase orders on the committed basis). Nothing here writes — no Bill, no JournalEntry, no Budget, no Payment. The 6.11 inbound_tracking / 6.12 receiving_console shape. Nothing on this page does arithmetic. A template that computes is a second implementation of a metric under the same name, and the two drift. SCM 4.11 (scm:spend_analytics) stays the COMMITTED/PO cube for negotiated savings and cycle time. It is LINKED from here, never restated — two pages printing the same metric under one name is how they start disagreeing. Context consumed: kpis (whose eight values are each a scalar result dict, so a cell reads kpis.net_spend.display), by_supplier, by_category, by_department, by_gl_account (each a list of {label, pk, value, display, pct, count} — pk is None for the (unassigned)/(Unclassified) bucket, which is why every drill link is wrapped in {% templatetag openblock %} if row.pk {% templatetag closeblock %}), trend, currency_rows, mixed_currency, basis, basis_choices, range_key, date_range_choices, start, end, stats, scm_analytics_url, department_caveat, maverick_dashboard_url, category_spend_url, workbench_url, export_url. Two pinned keys are deliberately NOT consumed here, and the reason is in the return note rather than invented into a wrong link: drill_url_name — the literal "procurement:supplierinvoice_detail". It takes a SupplierInvoice pk, and this page's context carries no invoice row anywhere; the breakdown pks are Party / ItemCategory / OrgUnit / GLAccount. Feeding one of those to an invoice route would resolve to a real URL pointing at somebody else's record, which is worse than no link. The breakdowns drill into category_spend by filter instead. There is no vendors / categories / org_units / gl_accounts option queryset in this context, so the FK filters this page honours get an active-filter chip rather than a fabricated dropdown. {% endcomment %}
