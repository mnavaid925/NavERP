Window

Two different windows, on purpose. The date range is the rolling window the live figure on the detail page and the control-tower tile are measured over. The period grain is the bucket ONE frozen trend point covers — rolling windows overlap, so a trend built from them would be meaningless.

{% include "partials/form_field.html" with field=form.period_grain %} {% include "partials/form_field.html" with field=form.date_range %}

Bands

All three bands are optional — a target with none still snapshots and trends its metric, it just cannot be banded. Whichever ones you set have to run the way the metric runs: lower-is-better climbs away from the goal (target, then warning, then critical), higher-is-better falls away from it. Leave direction blank to inherit the metric's own; set it only for a deliberately inverted goal.

Parameters

Some metrics are defined in terms of a number, and are not smaller without it — they are not a number at all. Dead stock, aging stock, expiry risk, supplier disruption and shipments-at-risk each need a days figure; carrying cost and demand-spike detection each need a percentage. The save is refused if the metric you chose needs one and it is blank.

Alerting

Alerting fires off the two thresholds, so turning it on with neither one set is refused rather than accepted — a tick-box that can never fire is worse than no tick-box, because you would believe you were covered. The minimum impact is the alert-fatigue floor: a breach worth less than it raises nothing.

Display

Pinned targets become tiles on the analytics control tower, lowest display order first. Deactivating a target keeps it and its frozen history — the batch capture and the alert detector both skip it, so it simply stops accruing new points.
