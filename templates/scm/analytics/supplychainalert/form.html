The title is the one line the queue is read by, so write what is wrong rather than what it is called. A KPI target and a metric have to describe the same figure: naming a target adopts its metric, and naming a different one is refused, because the "open the report" link on the detail page would otherwise land on the wrong page. Measurement

The measured figure and what it was measured against are both optional — an exception a person spotted often has no number behind it. Value at risk is what the inbox is ordered by, biggest first, so an exception left at zero sits below every costed one; that is the right place for something nobody has priced, but if you know roughly what acting on this is worth, say so. It is a magnitude and cannot be negative. The subject label is the line the queue shows: leave it blank and it falls back to whichever record you name below, and to "Network-wide" when you name none.

Subject

Set the ones that apply. Each becomes a one-click link on the detail page, and that link is the whole difference between an exception somebody can act on and a number somebody has to go hunting for. They are offered in full rather than narrowed — an exception can be about a wound-down location or a cancelled order. Two combinations are checked on save: a shipment and a carrier must be the same movement, and a purchase order and a counterparty must be the same supplier, because otherwise the detail page points at two unrelated things. Every record named is checked against this workspace however the form was submitted.

{% comment %} EVERY LIFECYCLE COLUMN IS ACTION-ONLY AND IS DELIBERATELY ABSENT FROM THIS FORM. status, snoozed_until, acknowledged_by/_at, resolved_by/_at, resolution_note, raised_at, last_seen_at, number, dedupe_key, dimension_key and detail are none of them on SupplyChainAlertForm.Meta.fields. They are written only by the five workflow methods on the model, reached from the buttons on the detail page (acknowledge / assign / snooze / resolve / dismiss), so each one keeps exactly one writer and the audit trail records what happened rather than what somebody typed. A resolution note in particular cannot exist without a resolver and a timestamp beside it, which is only true while resolve() is its only writer. assigned_to is the ONE triage column that IS here, deliberately: it is a name, not a state. It is rendered even on a closed exception rather than hidden — an unrendered field posts nothing, which the form would read as "un-assign" and then refuse. The form refuses a CHANGE to it on a closed alert instead, which is the same rule assign() enforces. {% endcomment %}

Ownership

Putting a name on an exception is the step that stops it being everybody's and therefore nobody's; leave it blank and it shows up under "Unassigned" in the inbox. Deactivated logins are not offered — work handed to a login nobody signs into is a queue item nobody sees — but whoever already holds this alert stays selectable. No other triage column is on this form: status, the snooze window and the acknowledged/closed stamps are written only by the buttons on the detail page, and the alert number is issued on save.
