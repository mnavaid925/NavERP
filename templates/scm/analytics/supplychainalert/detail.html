{% comment %} Stating the three non-obvious lifecycle rules the model enforces, so the page and the code agree: a snooze window is dropped rather than kept as history when the alert leaves that state (so "is this still suppressed?" stays answerable); dismiss shares resolve's attribution pair, because there is deliberately no dismissed_by — an unattributed close is an audit hole; and assignment records a name but no timestamp, which is why that row shows no time rather than inventing one. {% endcomment %} Snoozing is suppression, not closure. A snoozed alert returns to the queue on its own once the window runs out, and the window is cleared — not kept as history — the moment the alert moves to any other state. Resolving and dismissing are both terminal and both recorded against the same person and time: the status is what says whether the exception was fixed or judged not worth acting on. Assignment records a name and no timestamp, so that row deliberately shows none.
