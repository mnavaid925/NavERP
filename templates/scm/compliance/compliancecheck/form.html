Everything this page may read, and nothing else: * form — ComplianceCheckForm (bound on POST) * is_edit — always True; a check is only ever CREATED inline from its requirement's detail page, so this template exists solely to correct one that already exists * obj — the ComplianceCheck being corrected * requirement — obj.requirement, for the breadcrumb and the Cancel target There is deliberately no create path here and no list/detail page for this model: a check is a tenant-less child reached only through requirement__tenant, and it is rendered as a timeline on its parent. The seven names below are ComplianceCheckForm's whole whitelist. Absent by design: `requirement` (it comes from the URL — letting a POST choose its own parent is how a check lands on somebody else's obligation), `performed_by` (stamped from request.user; who proved a control is an audit fact, not an input) and `created_at`. Editing a check does NOT re-run the parent's projection — the view refuses to let `result` or `due_date` change here, because re-deriving would advance the due date a second time for a cycle that already advanced it. That rule lives in the view, not in this template. {% endcomment %} {% block title %}Edit Check · {{ requirement.number }}{% endblock %} {% block content %}
