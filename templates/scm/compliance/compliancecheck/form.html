Renders apps/scm/views/ContractCompliance/ComplianceRequirements.py::compliancecheck_edit. Everything this page may read, and nothing else: * form — ComplianceCheckForm (bound on POST) * requirement — obj.requirement, for the breadcrumb and the Cancel target The view also passes `is_edit` and `obj`; this page reads neither, because there is no create path to branch on (a check is only ever CREATED inline from its requirement's detail page) and the requirement carries everything the header needs. There is deliberately no create path here and no list/detail page for this model: a check is a tenant-less child reached only through requirement__tenant, and it is rendered as a timeline on its parent. The seven names below are ComplianceCheckForm's whole whitelist. Absent by design: `requirement` (it comes from the URL — letting a POST choose its own parent is how a check lands on somebody else's obligation), `performed_by` (stamped from request.user; who proved a control is an audit fact, not an input) and `created_at`. Every field here IS editable, including `result` and `due_date` — this is the correction path. What the view deliberately does NOT do is re-run the parent's projection: re-deriving would advance `next_due_date` a second time for a cycle that already advanced it. So a changed verdict fixes the record and the derived `compliance_rate`, but the requirement's own status and due date stay where they are until somebody sets them on the requirement's edit screen. The view flashes exactly that when `result` changes. {% endcomment %} {% block title %}Edit Check · {{ requirement.number }}{% endblock %} {% block content %}
