Labour Plans

Supply Chain›Labour Plans

A plan is an artefact, not a screen: one row per staffing question — this site, these dates, this grain — generated once from the live ledgers and then reviewed by a human. That matters because the volumes it was built from keep moving. A plan computed live would silently re-answer last week's staffing question with this week's data, and nobody could ever say what the roster was actually decided on. The set of activities a plan covers is a consequence of the standards library rather than a list somebody maintains: an activity with no active standard has no minutes to plan with and is not planned.

No labour plans

Nobody has written a staffing question yet. Create one here — a site, a period and a grain — and it starts as a draft with no grid at all. Pressing Generate on its own page is what derives the volume from the live ledgers, prices it against the standards library and builds one line per bucket × activity; that press is the only route into planned. If you were expecting rows here, try clearing the filters.
