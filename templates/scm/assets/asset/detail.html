Reliability — and how each number is derived

Computed on read · nothing below is stored
MTBF
{% if mtbf_hours is not None %}{{ mtbf_hours|floatformat:2 }} h{% else %}—{% endif %}
(observation window − downtime) ÷ failures — uptime over failures, not elapsed time over failures, so an asset that spent half the window in pieces is not flattered for having been broken. {% if mtbf_hours is None %} {% if failure_count %} There are {{ failure_count }} failure{{ failure_count|pluralize }} on record but the observation window could not be established — nothing gives the clock a start earlier than now, which usually means the commissioning date is set in the future. Not zero — unmeasured. {% else %} No failures recorded yet, so there is no denominator. A 0 h MTBF would read as "fails constantly", which is the exact opposite of the truth. {% endif %} {% endif %}
MTTR
{% if mttr_hours is not None %}{{ mttr_hours|floatformat:2 }} h{% else %}—{% endif %}
downtime on completed and closed breakdowns ÷ the count of those breakdowns. A repair still in progress has no repair time yet, so it is excluded from both sides rather than divided into the average — otherwise the figure would sag every time something is currently broken, which is the moment it is most looked at. {% if mttr_hours is None %} No breakdown has been finished yet — the honest answer is "not enough history", and a 0 h MTTR would read as instant repairs. {% endif %}
Availability
{% if availability_pct is not None %}{{ availability_pct|floatformat:2 }}%{% else %}—{% endif %}
(window − {{ downtime_hours|floatformat:2 }} h) ÷ window × 100. It is not clamped to anything but zero: when the recorded downtime exceeds the window the answer is 0%, which is visibly wrong and sends somebody to look at the data — silently rounding it up to something plausible would not. {% if availability_pct is None %} No observation window could be established — nothing gives the clock a start earlier than now — so there is nothing to measure against. Blank, not 0%. {% endif %}
Observation window
{% if obj.commissioned_on %} Opens {{ obj.commissioned_on|date:"M d, Y" }} {% else %} Opens {{ obj.created_at|date:"M d, Y" }} {% endif %} → now
{% if obj.commissioned_on %} The commissioning date — when the asset entered service and the reliability clock started. {% else %} No commissioning date so the window falls back to when this record was created. Set Commissioned on to measure from the day the machine actually entered service. {% endif %} The window is deliberately not "since the first work order", which would give an asset with no jobs a zero-length window and therefore 100% availability by construction.
Total downtime
{{ downtime_hours|floatformat:2 }} h {% if is_down_now %}Still down{% endif %}
{{ downtime_minutes }} min ÷ 60. Includes any window that is still open, measured to right now — a job stores its downtime when the window closes, so a machine that has been down three days would otherwise report none at all while the chip above said it was down.
Failures
{{ failure_count }}
Work orders of type Breakdown, cancelled ones excluded, counted on the date the fault was reported. Planned corrective work — a scheduled bearing change — is repair, not breakdown, and counting it would depress MTBF for doing maintenance properly.
Maintenance cost to date
{% if maintenance_cost_to_date is not None %}{{ maintenance_cost_to_date|floatformat:2 }}{% else %}—{% endif %}
Σ(issued part qty × unit cost at issue) + Σ(labour hours × rate) + Σ(contractor cost) across every non-cancelled job. Only issued parts count: a reserved line still carries 0.00 because its cost is stamped at issue time, and no stock has moved for it either.
Jobs
{{ open_work_order_count }} open of {{ work_order_count }}
Open means not completed, closed or cancelled. Stated as the terminal set rather than the open one on purpose, so a status added later counts as open and shows up here — erring towards putting a job in front of somebody.
