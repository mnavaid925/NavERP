Supply Chain›Client Billing Runs

One row per client per billing period: what the tariff says the warehouse did for them, priced from the evidence already in the ledger rather than typed by anybody. A run is a working document until it is invoiced — it can be recalculated as many times as you like while it is draft or calculated, and every recalculation rebuilds only the machine-derived lines and leaves manual charges alone. The last step hands one draft invoice to Accounts Receivable, which owns the money from there.

A billing run prices one client for one period against one rate card. Start it with New Billing Run: pick the client, pick the tariff that was in force, give the period, and save. Nothing is priced at that moment — you press Calculate on the run afterwards, and the figures come from the stock ledger, the receipts, the orders and the shipments that already happened, so there is no month-end spreadsheet to reconcile. If you were expecting rows here, try clearing the filters.

The total on a row is the stored figure the last calculation left behind, minimum adjustment included — it is not recomputed as you read this page, so a run whose underlying stock or orders have changed since shows the old number until somebody recalculates it. That is deliberate: an approved figure that quietly re-priced itself between the approval and the invoice would be the one number in this module nobody could trust. Delete disappears once a run is invoiced, because a draft invoice already exists in Accounts Receivable pointing back at it; void the run while it is still draft or calculated instead, which keeps every line as evidence.
