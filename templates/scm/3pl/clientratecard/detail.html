A rate card with no lines is not an error and a billing run against it will not fail — it will simply calculate to zero and say so, which is exactly what "we agreed the tariff but never filled it in" looks like. Add the lines the contract actually contains: storage per pallet position per month, a handling charge per order or per line, a receipt fee, a flat monthly account charge. Each line names one category and one basis, and the basis is what tells the run where to go counting.

Included quantity is the free allowance subtracted before billing, and the tier band is a plain from/to range on the measured quantity rather than an expression language: this module deliberately does not grow one, and a genuinely bespoke formula belongs in a contract clause and a manual line, not in a rate engine nobody can audit. {% endif %}
The per pallet position basis bills stock units one-for-one as pallet positions until items carry dimensions — the run says so on the line it writes. That is a stated approximation and never a hidden one; the bases listed as needing a manual quantity are simply not measurable from the data this system holds today, so they are written with a zero quantity and flagged for a person rather than being guessed at with an invented conversion factor.
