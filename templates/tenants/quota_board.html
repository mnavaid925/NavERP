What this board does not do

Quota enforcement and throttling are declined. A quota crossing its ceiling here changes nothing about the product: action_on_breach is a recorded policy with no interceptor, so the value in the On breach column is what somebody agreed to, not an instruction NavERP acts on. Nothing is throttled, nothing is charged, no request is blocked, and no alert is raised by crossing a line on this page.

Metered event ingestion is declined. The consumption column is 0.1’s UsageRecord register, and its rows are entered by hand or by 0.1’s flow. There is no event pipeline feeding this board, so the meter only moves when somebody records a row — it is not a live tap on product activity.

L36 — which rows are 0.1’s. This board is new in 0.19, but the rows underneath it are not: UsageRecord was built by sub-module 0.1 and is extended here, never re-declared. A quota reaches it by foreign key and reads the meter; the usage rows themselves belong to 0.1. If you are looking for a second usage table, there is none — reporting a duplicate-billing bug here would file it against the wrong sub-module.

Prepaid credit grants and rate-card, tiered or multi-currency pricing are declined app-wide: the overage column is consumption past a recorded number, and it is not priced by anything. Proration is declined too — no money arithmetic happens anywhere in this sub-module.
