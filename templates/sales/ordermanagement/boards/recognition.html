{% extends "base.html" %} {% comment %} Revenue Recognition board — the ASC 606 / IFRS 15 position across every schedule. This is the only board whose figures are MONEY, and every one of them is a @property on RevenueSchedule, read live: contract_amount IS SCM 4.5 own order total, and the rest are sums and differences over the schedule own obligations. None of them is a column, so none of them can be stale - and equally, none of them can be edited here. The stats strip is summed in PYTHON in the view, never with aggregate("Sum") on a Decimal: that is the SQLite integer-division trap SCM 4.5 names in recalc_totals(), and a contract value that reads back 12,345 instead of 12,345.67 is worse than no register at all. A VOID schedule is excluded from the money and counted separately, because a voided schedule is a document that was abandoned, not a position the company holds. The register own verbs (open a schedule, add an obligation, recognise) are deliberately NOT duplicated here. This is the portfolio view; the register one screen away owns the document. What the board adds is the cross-schedule total - the one number nobody can get from a paginated list. {% endcomment %} {% block title %}Revenue Recognition{% endblock %} {% block content %}
