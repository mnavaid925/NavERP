{% extends "base.html" %} {% comment %} Create / edit one OrderAmendment. One template serves both: `is_edit` and `obj` are pinned on BOTH create and edit (obj is None on create), so the Back link and the Cancel target are the only two things that differ. The five fields below are the WHOLE authorable surface. There is no status picker, no impact box and no timestamp field: those are the difference between a change-order register and a suggestion box, and the server owns all three (L22). The impact snapshot in particular is frozen evidence written by the server at propose time — a clerk who could type "no impact" into it would leave nothing to check. Editing is limited to a still-open amendment. A withdrawn, rejected, applied or superseded one is a closed document, and the view refuses the edit before this template is ever reached. {% endcomment %} {% block title %}{% if is_edit %}Edit Order Amendment{% else %}Propose Order Amendment{% endif %}{% endblock %} {% block content %}

FieldWhy it is not on this form
StatusWorkflow. A proposal starts as a draft, and only the Decide, Apply and Withdraw verbs move it — an edit form that could flip a withdrawn amendment back to approved would make the audit trail a suggestion.
Impact snapshotFrozen evidence, written by the server when you save and re-frozen whenever a proposed line changes: what each order line was, what the amendment proposes, and how far the order total moves. A snapshot typed by hand would be the account of the cost written by the person the cost happens to.
Requested / decided / appliedAction-stamped. Each is written by exactly one named button, and the actor is always the signed-in user — never a name typed into a form.
Proposed linesAdded on the amendment\'s own page, one at a time, through the parent. A line that reached its parent from a form field would be a way to append a change to somebody else\'s change order.
