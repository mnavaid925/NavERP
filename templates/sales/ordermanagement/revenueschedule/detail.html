{% comment %} THE FIVE-STEP READ-OUT. Every value here is a @property on RevenueSchedule, computed on read from the order and the obligations. None is a column; none can be edited; none can fall out of date. {% endcomment %}

The five steps, in ASC 606 order

Every figure below is derived, not stored. Nothing here is a column on the schedule and nothing here can be typed. Each one is worked out on the spot from the order's own total and from the obligations below, which is why they cannot go stale when an amendment re-prices the order, and why there is nothing to edit.

  1. 1 · Contract value — the price of the deal
    {{ schedule.contract_amount }}
    Read live from order {% if order %}{{ order.number }}{% else %}—{% endif %}'s total, which SCM 4.5 owns and recalculates. This module never copies it.
  2. 2 · Allocated — what the obligations say it is worth
    {{ schedule.allocated_amount }}
    The sum of each obligation's share of the contract price, quantised to cents in Python. Written to the obligations only by recompute().
  3. 3 · Recognised — what has actually been earned
    {{ schedule.recognized_amount }}
    {{ schedule.recognition_progress_pct }}% of allocated. Moves only when somebody presses Recognise on an active schedule, and only as far as the passed recognition dates allow.
  4. 4 · Deferred — paid for, not yet earned
    {{ schedule.deferred_amount }}
    Allocated less recognised, floored at zero. Never negative.
  5. 5 · The balance, whichever side it falls on
    {% if schedule.contract_asset > 0 %}
    Contract asset {{ schedule.contract_asset }}
    More is recognised than allocated — the customer owes for work already delivered. This is the asset side, and it is why "deferred" alone would be the wrong word.
    {% elif schedule.contract_liability > 0 %}
    Contract liability {{ schedule.contract_liability }}
    More is allocated than recognised — revenue taken ahead of performance and held. Numerically the same gap as the deferred figure; the standard names it a liability.
    {% else %}
    In balance 0.00
    Allocated and recognised agree, so there is neither a contract asset nor a contract liability.
    {% endif %}
