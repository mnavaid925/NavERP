{% extends "base.html" %} {% comment %} Create / edit one QuotaPlan. ONE template for both, driven by `is_edit`. There is deliberately NO money field on this form. The target amount is `crm.SalesQuota.target_amount`, owned and edited by CRM 1.2; a money input here would be a second source of truth for the same number (L37). What this form records is the DERIVATION: the method, the basis, the baseline, the growth and relief percentages, whether uplift was permitted, and how it phases. `status` is off the form by decision, not by `editable=False`. It is moved by four POST verbs on the detail page — draft -> submitted -> approved | rejected -> locked — so a status dropdown would be a workflow engine written in a select element. The same reasoning puts `calculated_at` off the form: it is a fact about a past calculation, not an input. `quota_ref` and `forecast_period` are bound to each other in the model's clean(): both carry their own period fields and nothing in either schema stops them disagreeing, so the mismatch is refused here with a message naming both sides rather than surfacing later as a wrong attainment number. {% endcomment %} {% block title %}{% if is_edit %}Edit Quota Plan{% else %}New Quota Plan{% endif %}{% endblock %} {% block content %}

StatusWorkflow, not a preference. It is moved only by the Submit / Approve / Reject / Lock actions on the detail page, so a plan cannot be declared approved by the person who wrote it.
Period year / quarter / monthNot re-spelled here. The window is 8.4's ForecastPeriod, and a second copy of a window is how a Q2 quota ends up measured against a Q1 forecast.
