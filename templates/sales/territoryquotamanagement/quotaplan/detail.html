THE MONEY RULE. `derived_baseline` and `derived_stretch_amount` are `Decimal`s computed in PYTHON in the view. They are not stored columns and not `F()` expressions, and there is no money column on this model at all: a second stored target is a second source of truth for the same number. They are FORMATTED here, never calculated here. THE WORKFLOW. Status is moved by four POST verbs and nothing else — draft -> submitted, submitted -> approved or rejected, approved -> locked. Each verb is its own form with a csrf token and a confirm, and each is offered only where the SAME guard in the view will let it through, so the button and the refusal cannot disagree. Approve, Reject and Lock are tenant-admin only, which is what `can_approve` reports. `is_frozen` (approved or locked) withholds Edit here. That is a courtesy, not the guard — `quota_plan_edit` re-checks the same condition server-side. The quota and the forecast period are READ-ONLY on this page and are labelled as such: both belong to other modules (CRM 1.2 and Sales 8.4), and 8.7 never writes either one. {% endcomment %} {% block title %}{{ obj.number }} · Quota Plan{% endblock %} {% block content %}
