{% extends "base.html" %} {% comment %} 8.7 Quota plans — the DERIVATION behind a CRM quota target. 8.7 declares no quota and writes no money. The number is `crm.SalesQuota.target_amount`, owned by CRM 1.2, and this register only records HOW it was set: method, allocation basis, baseline, growth, attrition relief, whether uplift was permitted, and how it phases. That is why there is no money column on the form and why the status is moved only by the four POST verbs. Status is ACTION-DRIVEN (draft -> submitted -> approved | rejected -> locked), never typed. A status picker on a form is a workflow engine written in a dropdown. Every badge below keys on the exact choice value with an {% else %} get_status_display fallback. `is_frozen` is the view's own predicate (approved or locked) and is what withholds the Edit button here. Hiding the button is a courtesy, not the guard: `quota_plan_edit` re-checks the same condition server-side, so a crafted POST is refused too. ENUM filters read their ECHO keys; FK dropdown compares are `|stringformat:"d"` against `request.GET.territory` / `request.GET.owner` / `request.GET.forecast_period` — never `|slugify` on a pk (contract §11.1 rule 3). {% endcomment %} {% block title %}Quota Plans{% endblock %} {% block content %}
