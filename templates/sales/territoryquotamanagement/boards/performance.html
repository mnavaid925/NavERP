{% extends "base.html" %} {% comment %} 8.7 Territory performance — attainment per territory for ONE forecast period. THE MONEY RULE. Every money and percentage figure on this page is a `Decimal` computed in PYTHON in the view, over a fetched set. It is never `Sum()`, never `F()`, never a database-side division, never a float. That matters here more than anywhere else in 8.7, because a board query is exactly where the temptation appears: an aggregate is one line and a Python loop is ten, and the SQLite integer-division trap SILENTLY drops fractional cents rather than raising — so an aggregate board is not a slow board, it is a wrong one that renders. Nothing on this page is calculated; figures are formatted, never computed. A `None` figure is a MISSING DENOMINATOR, not a zero. There is no quota for this period, or the deals are booked in more than one currency, and printing 0% in either case would assert an attainment the board did not measure. It is printed as withheld, and the reason is in `caveats`. PACING vs ATTAINMENT. Attainment is against the target; pacing is attainment against TIME. 120% of target halfway through the period is ahead of pace, and attainment alone cannot say so. Both are separate columns here for that reason. `balance_profile` is an ACCEPTANCE SPEC, not a score: every axis is reported and no single balance metric is invented, because equalising territories on one factor is the documented failure mode. LIVE DERIVATION, NOT A SNAPSHOT — recomputed on every load, never stored, and this page never writes. The quota amount it reads is `crm.SalesQuota.target_amount`, owned by CRM 1.2; the window is 8.4's `ForecastPeriod`. 8.7 writes neither. {% endcomment %} {% block title %}Territory Performance{% endblock %} {% block content %}
