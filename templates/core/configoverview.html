What this module does NOT do

Settings are not a django.conf.settings replacement — get_setting() only resolves keys that exist as a registered definition, so a typo returns the caller's default rather than inventing a value. Numbering configures but never allocates: every number is still minted by next_number(), and the reconciliation board covers NUMBER_PREFIX-based numbering plus the literal-prefix models listed on it. Fiscal periods and period-close controls live in accounting.FiscalPeriod, not here. Custom-field values are keyed without a foreign key and no module renders them yet — a module must opt in. Declared here rather than implied.
