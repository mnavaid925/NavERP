What each active policy would dispose of. Nothing here destroys anything.

Automated destruction is deliberately not implemented. Destroying data is a one-way door, and this repo has no scheduler — the only way to automate it would be to make a page request destructive. Worse, the project already established that "delete" in this codebase does not erase bytes (Django never unlinks a FileField on row delete), so a destruction feature that reported success while the file survived would be actively dishonest. The schedule, the identification and the evidence are here; the act is out of band.
