### Things worth keeping — all cost a debugging round each

- **The test DB is SQLite, not MariaDB.** `pytest.ini` → `config.settings_test` → `sqlite3 :memory:`.
  SQLite also sorts NULLs **last** under `DESC`, so C5's defect reproduces and the ordering test is
  meaningful — but assert the OUTCOME, never a server-specific mechanism.
- **A `ModelForm` refusal is not a database one.** `DataArchive.location` is `blank=False` (form refuses
  `""`) but the column accepts it and the seeder writes it. Fixture helpers take `_validate=True` and the
  deliberately-invalid states opt out.
- **`created_at` is `auto_now_add`**, so a past-expiry `EnvironmentInstance` is unbuildable through
  `full_clean()`, and the retention board's "due" figure can only be exercised by creating rows then
  backdating with `.update()`.
- **`RecoveryPosture.tenant` is a `OneToOneField`** — one posture per tenant, so two posture fixtures
  cannot share a workspace.
- **`LegalHoldForm` has no `issued_at` field**, which is *why* C3's incoherent state is reachable only on
  the EDIT path: the create path always has `issued_at = now` and trips rule 1 first.
- **`form.initial` carries the related PK (an int) for a FK**, not the instance — `value.pk` raises.
- **`unverifiable_count` is a `backup_board` key, not a hub key** — two pages, two separate zero-rule rows.
- **`ConsentRecord.purpose` is a FK to `ConsentPurpose`**, not a string.
- **`RestoreRecord` refuses a restore with no source** ("cannot be audited").
- **The tenant-less superuser behaves differently by route**: boards/hub/create pages redirect; the six
  list pages return 200 with an EMPTY list (`filter(tenant=None)` matches nothing). Neither leaks —
  pinned as-is rather than silently encoding one half as "correct".
