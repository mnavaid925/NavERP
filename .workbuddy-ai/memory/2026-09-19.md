### The design decision that mattered: a registry alone is decoration
0.6's thirteen bullets are thirteen per-module access scopes sharing ONE shape, so they are one
registry with a row per module. But a config table nothing reads is exactly the failure mode I
criticised in 0.1, so the build is a registry **plus one real enforcement point**:

  both pure functions.
- `crud_list()` gained an **opt-in** `scope_module`/`scope_owner_field` hook, applied **before**

- `core:activity_list` wired as the **in-situ proof** (Activity.owner exists, view is member-facing):
  at `data_scope=own` a member sees only their own rows, an admin sees all, a disabled scope restores
  everything. **One view, not 150, on purpose** — retrofitting row-level security across every list
  means auditing each for the right owner field, and a wrong guess silently empties a register. The
  access matrix reports which modules enforce, so the gap is visible rather than implied.

## 0.8 Privacy & Data Protection — closed out

**0 of 5 bullets mapped; no privacy layer existed.** Module 0 is now **10 of 21 built**;
11 remain (0.10–0.13, 0.15–0.21). Migration `core.0007`.

### Four decisions that make it honest rather than decorative
1. **A withdrawal ADDS a consent row** and the effective state is DERIVED from the latest event
   (`current_consent()`), never a stored flag a withdrawal could fail to update. An expired grant
   reads as no consent.
2. **A DSAR with no framework enabled gets NO due date** — `statutory_window_days()` returns `None`
   rather than a default 30, because a deadline the workspace cannot point at a regime for is a
   fabricated obligation. Two frameworks enabled → the **strictest** wins (GDPR 30 beats CCPA 45).
3. **Completion is blocked until identity is verified** — a verb with a required note, not a checkbox.
4. **Automated destruction is NOT implemented, and the page says why.** One-way door + no scheduler +
   the 7.10 finding that "delete" here does not erase bytes. The board identifies; the disposal
   register evidences; the act is out of band.

### The retention board refuses a misleading zero
It reports WHY it cannot evaluate a policy (no `created_at`, no `tenant`, no model pinned, bad label)
instead of showing `0`. **A zero that means "cannot tell" is the most dangerous number a compliance
board can show.**

### Two PII-scan false-positive classes found by probing (284 → 177 candidates)
- `model._meta.get_fields()` returns **reverse relations / M2M accessors** too, named after the
  related model's `related_name` → the first pass reported `core.Tenant.health_metrics` and 280 other
  accessors holding no data. Use **`concrete_fields`**.
- A bare `location` pattern matched **46 warehouse locations** (`qc_location`, `dock_location`,
  `from_location`…). A bin is not a person's whereabouts. Narrow the pattern; skip `is_`/`has_` flags.
- The scan is **non-destructive on re-run**: a confirmed/dismissed row is never touched. Verified.

### Probe lesson (cost a round trip)
A consent-expiry assertion failed because the probe back-dated the expired grant onto a purpose whose
latest event was already a withdrawal — so it read the withdrawal, not the expiry. **A
derived-from-latest query needs its own isolated fixture**; sharing a purpose with other events tests
ordering, not the rule. (The code was correct; the probe was wrong. Fourth time today that a failing
check turned out to be the probe — and the first today where it was the code. Keep checking both ways.)

### A false negative found by probing the board
The board reported **SINV as "nothing mints it"** — wrong: `tenants.SubscriptionInvoice` predates

that reading the code would not have.**

### THE TRAP OF THE DAY — a JSONField form field eats your clean()
**A model `JSONField` gets a `forms.JSONField`, which validates as JSON in `to_python` — BEFORE any
`clean_<field>` or `clean()` runs.** So typing `a, b` for `choices` or `a` as a custom value failed
validation and the conversion code never executed: **two forms were silently unusable**. The smoke
probe caught it three times. `choices` (both definition forms) and `value` are now `CharField`.
**Rule: when adding a `clean_*` for a JSONField, redeclare the form field or the clean never runs.**

- `TenantModelForm` narrows `ModelChoiceField` only — **NOT `ModelMultipleChoiceField`**. Every M2M to
  a tenant-scoped model (0.6's `exempt_roles`, 0.10's `exempt_roles`) needs an explicit queryset or the
  picker lists other workspaces' rows.
- A cross-module `{% url %}` in a new template is a real break risk: I linked
  `accounting:fiscalperiod_list`, which does not exist (it is `fiscal_period_list`). **Verify every
  cross-module route name against `LIVE_LINKS` before using it** — the smoke probe caught it, the
  template render would have 500'd.
- `apps/core/views/_common.py` exports neither `timezone`, `messages`, `redirect`, `Count` nor
  `write_audit_log` — a new core view file must import each explicitly. Hit this twice today.
