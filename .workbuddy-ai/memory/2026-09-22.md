## The review was worth its cost — 1C / 4I / 7M, all fixed

Six serial lanes → `review-core-0.15.md` (958 lines). Two findings are worth keeping:

1. **C1 — a `unique_together` containing `tenant` is NEVER validated by a `ModelForm`.** `tenant` is not a
   `Meta.fields` member, so `Model._get_unique_checks()` drops the whole tuple. The form validates,
   `crud_create` saves, MySQL raises `IntegrityError` → **an unhandled 500 on both create and edit** for the
   everyday action of typing an existing name. **This is a repo-wide shape, not a 0.15 bug** — any model with
   `unique_together = (tenant, <field>)` and a `ModelForm` that excludes `tenant` has it. The guard belongs in
   the form (`clean_<field>`, scoped to `self.tenant`, excluding `self.instance.pk`); the existing reference is
   `apps/crm/forms/CustomerSuccess/HealthScores.py`. **Worth grepping repo-wide.**
2. **I2 — the code was slow but not wrong; the *reason I wrote for it* was wrong.** `_fx_rows` fetched the
   whole rate history to avoid a `Max("rate_date")` tie that `unique_together = ("tenant","currency","rate_date")`
   makes impossible. The performance lane proved it by A/B measurement, not argument. A future editor reading
   that docstring would have preserved a slow query to defend against a tie that cannot happen.

Also: **I1** — three member-reachable pages offered only admin-gated exits, including a **Cancel** button that
403'd; the save itself succeeded, so this was a UX dead end, not a security hole (I overruled a lane that
graded it Critical). **I4** — the seeder's peer-app FKs could never populate on a *fresh* install, because
`seed_accounting` runs after `seed_core` and is the sole creator of `Currency`/`TaxCode`; the per-entity guard
then froze the NULLs permanently. Latent on the dev DB only because accounting data pre-existed.

## Process lessons (these are the reusable part)

- **Verify a lane's PREMISE, not just its reasoning.** Two of the seven lanes filed findings caused by **my
  own prompt**: I told the QA lane to expect a `tenant is None` redirect on the `statutory_rule_*` views, and
  the house norm is the opposite — **0 of 487** `crud_list` call sites guard it, and `party_list` is
  structurally identical. The lane even said it filed the finding only because my brief asserted it.
  Recording an orchestrator error is part of the job; the two are in the review file's no-action table.
- **A lane that measures beats a lane that argues.** The performance lane's A/B output is what made I2
  undeniable. The QA lane found the Critical only because it **refused to re-run the existing smoke harness**
  and covered the write paths instead — and it left the dev DB byte-identical, with before/after counts for
  nine tables.
- **A rate-limited agent may have already done work.** The first `code-fixer` attempt returned a 429 *after
  being created* — and had committed **13 fixes** before dying. The second pass had to discover that inherited
  state rather than assume a clean tree. **Re-read `git log` before re-running a failed agent.**
- **Never parallel-`Edit` the same file.** Four edits to one file in one message raced and lost two, leaving
  `Min` imported while `Max` was still called — every request 500'd and it looked like a broken test lane.
  Sequential edits only.
- **pytest fixtures are LAZY.** An exact count pinned from a probe that requested `member_user` read **1**, not
  2, in a lane that never asked for it. Name the fixture in the signature or the figure encodes a fixture-graph
  accident. (This cost the dashboard lane earlier today too.)

**Two traps this run added to the project's list:**
- **`manage.py shell < script.py` cannot run an indented block.** The interactive console executes stdin
  line-by-line, so every `for`/`if` body arrives as its own statement → `IndentationError` everywhere (and the
  half-executed script leaves side effects). A `temp/` sweep needs `sys.path.insert(0, <project root>)` and
  `python temp/x.py`. The sibling `_4_15_empty_sweep.py` has no such insert, so it was NOT run this way.
- **This project's `User.objects.create_user()` requires `email` positionally** — omitting it raises
  `TypeError: missing 1 required positional argument: 'email'`, which in a savepoint block aborts the tenant
  setup and silently skips the whole empty phase.
